# Gidubba 1.5.0

Gidubba 1.5.0 makes linked tables and Unique Results easier to use. You can go back to the table you started from, the
table list always shows which table you are on, and the Unique controls are easier to find. **Your data is not changed:**
Gidubba 1.4.0 can still open it afterwards.

## Highlights

- New: **Back to the original table.** After following one or more links, by hand or with Auto-follow, a **← Back to …**
  button above **Roll** names the table you started from. It makes that table the current one again, as a new step at
  the bottom of the screen. Every earlier result stays where it is. Back never rolls, and never happens by itself.
- New: **The table list follows the Roll screen.** When you follow a link (or go back), the list selects the table you
  are now rolling on, without opening anything or changing your results. **Edit table** and **Delete table** act on
  that table. If the list's folder or search hides it, nothing is selected, and Edit and Delete are unavailable until
  it is shown, so they can never act on a different table.
  - The selected table is clearly marked, with a gold bar, a tinted background and its name in bold, even while you are
    working on the Roll screen.
- New: **Help & Tips**, at the bottom of the window, opens the
  [Gidubba guide](https://rpgfrequencies.com/gidubba-guide.html) in your web browser.
- **Unique Results are easier to use.**
  - **Reset Used Results…** and the "Unique results: N of M used" count now sit right under **Roll**, so they stay in
    view after every roll.
  - The **Unique** and **Used** tags are small, quiet labels right after each result's text, instead of at the far
    right of the window. They are the same in tables shown as side-by-side columns.
  - In Edit table, **Mark All Unique** and **Clear Unique** are above the rows, just after **Clear Formatting**, so a
    long table needs no scrolling to reach them. On a narrow window they move to the next line.
- **See a table's options while rolling.** A small grey line under **Roll** shows the current table's options:
  **Clamp: On**, **Off** or **Not available** (hover to see why, for example on d66 tables), and **Manual selection:
  On** or **Off**. It follows the table you are on, including after following a link or going back. It is read-only;
  change these options in **Edit table**.
- **A hint when a modifier misses the table.** If a situational modifier takes a roll past a table's lowest or highest
  row, a note under **Roll** suggests turning on Clamp in Edit table. The result itself, Recent rolls and the Streaming
  Overlay are unchanged.
- **Clearer confirmations.** Each question now has a title naming what it does, such as "Delete Table" or "Reset Used
  Results". The questions and their buttons are unchanged.
- **The data format does not change** (still database schema version 12), and collection files are unchanged. See Data
  and Upgrades.
- **The installer, the program's folder and your data folder are unchanged.**

## Installation

1. Download `Gidubba-1.5.0-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If Gidubba 1.4.0 (or an earlier Gidubba or TableForge) is installed, leave it installed: 1.5.0 replaces it in place.
3. Start **Gidubba** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

Gidubba is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\Gidubba-1.5.0-Setup.exe` in PowerShell.

Also attached: `Gidubba-1.5.0-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`. It uses the same data folder.

## Known Issues

- **Back adds a new step.** Going back shows the original table again as a new step at the bottom, "Not rolled yet",
  with your earlier results above it. This is by design: the screen always reads from top to bottom in the order things
  happened.
- Help & Tips needs a web browser and an internet connection. There is no keyboard shortcut for it.
- Unchanged from 1.4.0:
  - Which Unique results have been used is kept on this computer only. It is not in exported collection files, and
    there is no undo for a single used result: **Reset Used Results…** resets the whole table.
  - With dddice, a table with few unused results left may use all 10 throws without landing on one. Nothing is used up;
    roll again, type a result, or switch to Built-in dice, which try far more often.
  - Exports to other programs leave out Unique: PUM Companion, Foundry and Tables+ can roll a used row again.
  - Collection files with Unique rows (format version 3) cannot be imported by 1.3.0 or earlier.
  - Some technical names still say TableForge, on purpose, so that existing installations, data and files keep working:
    the program file `TableForge.exe`, its install folder, the data folder `%LOCALAPPDATA%\TableForge`, the database
    file `tableforge.db` and the `.tfcollection` file type.
  - Auto-follow follows one link per result, and no further than 8 tables in one chain. It never chooses for you on a
    Manual-selection table.
  - PUM Companion export: **Not checked in PUM Companion:** rows beyond the dice, reached only through PUM's own roll
    overrides. Not exported: table descriptions. Inline dice are not rolled by PUM. A nested roll in PUM rolls the
    linked table once, even if the result's text says "roll twice".
  - **Questline import has not been verified.**
  - Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry
    does not reproduce Clamp.
  - Tables+ export: **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables; this is not full
    Tables+ compatibility. Several dice with a modifier (`2d6+1`) are refused.
  - Copy for Sojour was tested by pasting with Ctrl+V only.
  - Import Collection always adds a new collection, and Delete Collection cannot be undone.
  - Image-only or scanned PDFs need OCR first, and unusual PDF layouts may need manual cleanup.
  - dddice needs internet and WebView2.
  - Windows x64 only. Only one copy of Gidubba should be open at a time. Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing 1.5.0 over
1.4.0 keeps them, uninstalling Gidubba does **not** delete them, and reinstalling finds them again. To back up, close
Gidubba and copy that folder.

- **The data format does not change** (still database schema version 12). No safety copy is made, because nothing is
  updated, and no new settings files are added.
- **Gidubba 1.4.0 can still open data that 1.5.0 has used.** To go back, reinstall 1.4.0; your tables, used results and
  settings are all kept.
- **Collection files are unchanged.** Exports from 1.5.0 and 1.4.0 import into each other.

Updating straight from Gidubba 1.3.0 or earlier works exactly as updating to 1.4.0 does: the first start updates your
data and saves a safety copy first, and the older version cannot open the data afterwards. Read the 1.4.0 release notes
before updating from 1.3.0 or earlier.

## Feedback

Please report problems on [GitHub Issues](https://github.com/Gwydione/Gidubba/issues). Include your Gidubba version,
your Windows version, what you were doing and any error message. For Unique Results problems, say whether you used
Built-in dice or dddice. For export problems, also include the export report (**Copy Report**) where there is one.
**Never post dddice tokens or account credentials.**
