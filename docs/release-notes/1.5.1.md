# Gidubba 1.5.1

Gidubba 1.5.1 is a maintenance release for people who connect a dddice account. A connected account now keeps using its
own dddice room after **Disconnect** and **Connect**, instead of creating a new room each time. Nothing else changes.
**Your data is not changed:** Gidubba 1.5.0 can still open it afterwards.

## Highlights

- **Fix: your dddice room is reused after Disconnect and Connect.** Before 1.5.1, every Disconnect followed by Connect
  made Gidubba create a new room on your dddice account, and on some accounts dddice eventually refused to create more.
  Now connecting the same account again, even after restarting Gidubba, reuses its room. An OBS dice source made from
  that room's Streaming tools keeps working.
- **Disconnect still removes your dddice login.** It deletes the login (the token) and your theme choice, as before.
  It keeps only your dddice account id and room id, which are not secret, in `dddice-rooms.json` in Gidubba's data
  folder. No password, token or other credential is ever stored there.
- **A room is only reused for the account it belongs to.** Gidubba checks with dddice that the room still exists and
  belongs to the connected account before using it. Connecting a different dddice account gives that account its own
  room. Switching back reuses the first account's room.
- **A clearer message when dddice will not create a room.** If dddice refuses to create a room (HTTP 402), Gidubba now says:
  "dddice would not create a room for Gidubba (402). Your dddice account may have reached its room limit. Delete rooms
  you no longer use on dddice.com, then Try again." Gidubba does not try again by itself. If dddice is busy or
  unreachable while Gidubba checks your room, it says so and creates nothing.
- **Unchanged:** guest dice, rolling and results, collections and exports, the Streaming Overlay, the installer, the
  program's folder and your data folder. **The data format does not change** (still database schema version 12).

## Installation

1. Download `Gidubba-1.5.1-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If Gidubba 1.5.0 (or an earlier Gidubba or TableForge) is installed, leave it installed: 1.5.1 replaces it in place.
3. Start **Gidubba** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

Gidubba is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\Gidubba-1.5.1-Setup.exe` in PowerShell.

Also attached: `Gidubba-1.5.1-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`. It uses the same data folder.

## Known Issues

- The first time a dddice account connected under 1.5.0 or earlier is used with 1.5.1, Gidubba asks dddice which account
  it is and confirms that the saved room belongs to it. If dddice cannot confirm this, Gidubba creates one new room for the
  account and shows "dddice room changed. Your OBS dice source may need to be updated." From then on that room is reused.
- Rooms created by earlier versions on Disconnect and Connect are not deleted by Gidubba. You can delete rooms you no
  longer use on dddice.com.
- Everything listed under Known Issues in the 1.5.0 release notes still applies.

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing 1.5.1 over
1.5.0 keeps them, uninstalling Gidubba does **not** delete them, and reinstalling finds them again.

- **The data format does not change** (still database schema version 12). No safety copy is made, because nothing is
  updated. Collection files are unchanged.
- New, only once a connected dddice account is used: `dddice-rooms.json` (your dddice account id and its room id; no
  credentials). `dddice-account.json` also records the account's dddice account id. Collection exports never include
  either file.
- **Gidubba 1.5.0 can still open data that 1.5.1 has used.** To go back, reinstall 1.5.0: your tables, settings and dddice
  connection are kept, and 1.5.0 ignores `dddice-rooms.json`.

## Feedback

Please report problems on [GitHub Issues](https://github.com/Gwydione/Gidubba/issues). Include your Gidubba version,
your Windows version, what you were doing and any error message. For dddice problems, say whether you were connected
to an account, and quote any message Gidubba showed.
**Never post dddice tokens or account credentials.** The contents of `dddice-account.json` must never be shared.
